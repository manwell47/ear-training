# Ear Training App - Project State & Architecture

Este documento sirve como "punto de guardado" (checkpoint) del estado actual de la aplicación, su arquitectura, y los últimos avances. Si necesitas retomar el proyecto con un nuevo agente o en otra sesión, proporcionarle este archivo le dará el contexto exacto de dónde estamos.

> **Nota de mantenimiento:** este archivo describe el código VIVO. El controlador es `src/web/App.js` y la hoja de estilos viva es `styles_v2.css`. Cualquier referencia a `App_v4x.js`, `App_temp*.js` o `styles.css` es legacy y no forma parte de la aplicación activa.

## 1. Visión General
Se trata de una aplicación web de entrenamiento auditivo (Ear Training) orientada a ingenieros de mezcla y productores. El objetivo es emular un entorno VST profesional (estilo FabFilter Pro-Q / Cubase 15 Pro) donde el usuario debe identificar modificaciones de ecualización en A/B/X usando pistas de audio reales o ruidos sintetizados.

## 2. Tecnologías y Stack
- **Frontend / UI**: HTML5, CSS Vanilla (diseño Dark/Glassmorphism premium, sin librerías externas).
- **Audio / DSP**: Web Audio API pura (`BiquadFilterNode`, `AnalyserNode`, `AudioBufferSourceNode`).
- **Gráficos**: Canvas 2D API (`Visualizer_v2.js`) para representación espectral y funciones de transferencia.
- **Módulos JS**: Arquitectura ES6 basada en clases, sin build step (se sirve directamente).
- **Cache-busting**: los `import` usan sufijos `?v=N` y `index.html` carga `./src/web/App.js?v=N`.

## 3. Arquitectura del Código (Módulos Principales)

- **`index.html` & `styles_v2.css`**: Contienen la interfaz principal. `styles_v2.css` es la hoja viva (referenciada en el `<head>`). Destaca la barra superior con el fader de volumen maestro fusionado con un vúmetro estilo hardware, el selector de dificultad (que se bloquea visualmente durante la partida), el dock inferior con el panel Surgical EQ y las tarjetas de resultados.
- **`src/web/App.js`**: El controlador principal (Main Controller). Orquesta la inicialización, enlaza los eventos del DOM (botones, canvas drag) con los managers lógicos, gestiona los estados de pantalla (`setAppState`), el enrutado A/B/C, el Stem Mixer multitrack y los modales (Game Over, Level Up, Boss Defeat, Campaign Complete).
- **`src/web/AudioEngine.js`**: El corazón del DSP. Gestiona el ruteo de la señal (`switchMonitor` A/B/C), construye los grafos de ecualización (`buildGraph`) y carga las fuentes de audio. La carga de sesiones multitrack usa un pool de concurrencia acotada (`loadStemsWithConcurrency`, máx. 3 para no disparar el rate-limiting de GitHub Pages) y muestra el spinner global (`setLoadingSpinner`).
  - *Dato técnico vital*: Los parámetros de los filtros se ajustan estableciendo `.value` directamente además de `.setValueAtTime()` para garantizar la sincronización inmediata con las funciones matemáticas del Visualizador.
- **`src/web/AudioResourceManager.js`**: Gestor de recursos. Implementa Lazy Loading, una caché LRU acotada, eventos de carga (`onLoadStart` / `onLoadComplete` / `onLoadError`) y la lista maestra `AUDIO_SOURCES`. Exporta `AUDIO_BASE_PATH` (ruta ÚNICA de los OGG) y `pickRandomTargetStem()` (selección aleatoria de stem objetivo).
- **`src/web/AcousticMatrix.js`**: **Fuente única de verdad** del contenido didáctico de ecualización por clase acústica (`vocals`, `guitars`, `acoustic_guitar`, `bass`, `snare`, `kick`, `toms`, `drumbus`, `cymbals`, `room`, `strings`, `orchestra`, `woodwinds`, `flute`, `brass`, `trumpet`, `keys`, `piano`, `organ`, `epiano`, `percussion`, `master`, `synthetic`, `generic`). Expone `resolveAcousticClassKey()` y `ACOUSTIC_CLASS_ALIASES` para normalizar cualquier nombre de pista a una clave de clase.
- **`src/web/Visualizer_v2.js`**: Motor gráfico 60FPS. Dibuja el Analizador de Espectro RTA (azul cyan), la curva objetivo (naranja brillante) y la curva del usuario interactiva (púrpura). Calcula las curvas de filtro interrogando la respuesta en frecuencia de los nodos WebAudio reales.
- **`src/web/ScoringEngine.js`**: Motor de puntuación algorítmica. Puntúa Frecuencia (70%) y Ganancia (30%) de forma independiente. El feedback pedagógico (`getPedagogicalFeedback`, `analyzeProPractices`) se alimenta de `AcousticMatrix` a través de `resolveAcousticClassKey()`; la antigua `ContextMatrix` fue eliminada por duplicada.
- **`src/web/TrainingManager.js`**: La máquina de estados del juego (vidas, rachas, stages, combates con "Jefes"). Selecciona los objetivos (`generateAcousticTarget`) con criterio *audibility-first*.
  - *Dato técnico vital*: `resolveAcousticClass()` honra la clase del instrumento cargado y, si la fuente es genérica, rota por `LESSON_ROSTER` para variar el repertorio. La ganancia se acota por dificultad con `_audibilityBounds()` (Fácil 6–12 dB, Normal 5–12 dB, Hard 3–9 dB) y se pondera al alza en shelves/bells anchos. En sesiones multitrack (`isMultitrackSession`) se suma un desplazamiento fijo de +2.5 dB y el techo sube a 14 dB, para que el filtro no quede enmascarado por el conjunto.
- **`src/web/GameLoopManager.js`**: Store observable de progresión (`currentLevel`, `currentStage`, `totalScore`, `lives`, `streak`, `activeDifficulty`, `activeGameMode`, etc.). `TrainingManager` lo expone como `trainer.gameLoopStore` para mantener una única fuente de verdad de la progresión.
- **`src/web/VUMeter.js`**: Vúmetros por stem del Stem Mixer.
- **`src/web/dynamics-processor.js`**: **DSP del modo Dynamic Range**. `AudioWorkletProcessor` (`DynamicsProcessor`) con `numberOfInputs: 2` (0 = programa, 1 = sidechain externo), `numberOfOutputs: 1` (`outputChannelCount: [2]`). Implementa compresión *downward* y *upward*, knee cuadrático suave, attack/release/hold, release dependiente de programa, makeup + auto-gain, mix dry/wet, detector peak/RMS, feed-forward/feedback, stereo-link y coloración armónica **condicionada por el switch Color**. Emite telemetría por `port.postMessage` (~47-48 Hz) — **no** usa SharedArrayBuffer (GitHub Pages carece de COOP/COEP).
- **`src/web/dynamics-math.js`**: **Fuente única de verdad** del cálculo de dinámica puro (sin DOM). Expone `DEFAULT_DYNAMICS_PARAMS`, `staticGainDb()` (downward, hard-knee), `upwardGainDb()` (espejo exacto de `-staticGainDb(-x,-T,R,W)`), `computeGainDb()`, `computeTransferCurve()`, `softSat()`/`asymSat()`/`colorShape()`, `sanitizeParams()` (clamps) y `DSP_STYLE` (color, releaseDepend, kneeScale, detector, feedback por tipo).
- **`src/web/DynamicsEngine.js`**: Envoltorio del AudioWorklet (`DYNAMICS_CACHE_VERSION`). Gestiona `init()`/`_init()`, el URL del processor con cache-buster (`_processorUrl()`), el envío de parámetros (`setParams`, `setBypass`, `setStyle`) y las conexiones (`connectSource`, `connectSidechain`, `connectOutput`, `disconnect`, `dispose`).
- **`src/web/DynamicsMatrix.js`**: **Fuente única de verdad** del contenido didáctico de dinámica. `COMPRESSOR_TYPES` (5 tipos: `vca`, `fet`, `opto`, `varimu`, `bus`; cada uno con `engine = DSP_STYLE[x]`), `COMPRESSOR_TYPE_ORDER`, `DYNAMICS_HELP` (20 claves de ayuda), `DYNAMICS_BUSES` (6 buses), `DYNAMICS_SCENARIOS` (10 escenarios), `DYNAMICS_LESSONS` (currículum), `DYNAMICS_CHALLENGES` (10 retos con `weights`) y `DYNAMICS_INTRO`. `listScenarios()`/`getScenarioById()` para consulta.
- **`src/web/CompressorUI.js`**: Renderer Canvas 2D estilo FabFilter Pro-C2. Dibuja grid, unidad, knee, curva de transferencia, handles arrastrables (`threshold`/`ratio`/`knee`), operating dot y medidor de reducción de ganancia. `TYPE_COLORS` + `setColor(on)` separan la coloración por tipo del estudio de la curva limpia. Publica hotspots (`curve, knee, threshold, ratio, meter`) para los tooltips. La **curva de transferencia es la única capa** del panel `#compressorCanvas` (ya no pinta ningún scope temporal de fondo).
- **`src/web/TooltipController.js`**: Ayuda contextual "mantén 1 s para explicar". `hitTestHotspots()` (pura) resuelve el hotspot bajo el cursor; `HOLD_MS = 1000`, `MOVE_TOLERANCE_PX = 6`. `setTeaching()`/`setEnabled()`/`show()`/`hide()` y gestión del temporizador de *hold*.
- **`src/web/DynamicsLab.js`**: Orquestador del modo (Explore / Theory / Challenge=Práctica Guiada / Case). **Sin DOM** (importable por el verificador). Mantiene `params` (sanitizados), la máquina de estados de práctica (`startChallenge`, `submitChallenge`, `nextChallenge`), los casos de estudio (`loadCase`, `checkCase`, `revealCaseTarget`), el desbloqueo curricular (`getUnlockedControls`/`getUnlockedDomIds`) y evalúa vía `ScoringEngine.evaluateDynamics()` con fallback no-throwing `{pending:true,…}`. Exporta además `DYNAMICS_CASE_STUDIES` (10 casos guiados), `describeSidechainCases()` (presets de sidechain validados contra `MULTITRACK_SESSIONS`), `describePracticeAchievements()` (checklist **cualitativo** `ok`/`close`/`miss` derivado del `breakdown` de `evaluateDynamics`, sin números — base de la Práctica Guiada) y `listExploreScenarios()` (escenarios agrupados por bus).
- **`src/web/TheoryPanel.js`**: Panel del sub-modo **Teoría**. Renderiza los bloques de `DYNAMICS_THEORY` e incluye una **envolvente ADSR interactiva** (demo de ataque/release). La geometría es pura y exportable (`ADSR_DEFAULTS`, `adsrVertices()`, `buildAdsrPath()`) para verificarse sin DOM; `class TheoryPanel` gestiona el render dentro de `#theoryPanel`.
- **`src/web/DynamicsScopeRenderer.js`**: Gráfica **temporal complementaria** a la curva de transferencia (estilo FabFilter C2). `class DynamicsScopeRenderer` (con `start`/`stop`/`destroy`/`resize`/`setTelemetry`) pinta bajo el panel de la curva, en `#dynScopeCanvas`, un **osciloscopio de barrido (min/max por columna)** del waveform de entrada **pre-compresor** —la forma real del transitorio, no una envolvente de pico achatada— y lo superpone con una **cinta diferenciada de reducción de ganancia**, ambos sobre el **mismo eje temporal** (con **auto-normalización**: el pico visible llena la gráfica y las etiquetas del eje siguen el nivel de referencia actual, vía `SCOPE_MAX_GAIN`/`SCOPE_HEADROOM`). Lee el waveform del `AudioEngine` (`getPreTimeDomainData`→`getTimeDomainData`) y la telemetría de GR (`grDb`). Montado por [`App._mountDynamicsScope()`](src/web/App.js:589); arranca/para con la superficie de dinámica. El **readout numérico** es de tipo **PRO**: `_updateMeter(blockMs, blockPeakDb, dt)` **integra el RMS** de la señal (media cuadrática con constante de tiempo `SCOPE_RMS_SECONDS` ≈ 300 ms —la lectura "media" de un medidor comercial, en vez del pico por-frame que parpadeaba—), promedia la GR (`SCOPE_GR_SECONDS`) y mantiene un **máximo congelado** (el pico más alto alcanzado, `maxPeakDb`, que **no decae**) que se pinta justo debajo del medidor y un **máximo congelado de reducción** (`maxGrDb`) que se pinta bajo `GR` para fijar el *make-up*; la rejilla de niveles se ancla a **fracciones de pantalla fijas**; toda la balística es **dt-dependiente** (idéntica a 30/60/144 fps) y los **dígitos se refrescan solo a `SCOPE_TEXT_HZ`** (6 Hz, no 60) para que el número se quede quieto, dando líneas `ENTRADA RMS`/`MÁX`/`GR` con 1 decimal (y `auto ×N`). Helpers puros exportados: `ampToDb()`, `dbToAmp()`, `peakToDb()`, `rmsAmp()`, `rmsToDb()`, `levelToY()`, `ampToY()`, `grToY()`, `pushHistory()`; constantes `SCOPE_COLUMNS` / `SCOPE_COLS_PER_FRAME`. Además, mientras el **Stem Mixer** está visible (multitrack), `.dynamics-panel` reserva `right: 320px` para no tapar el medidor de GR ni el lateral derecho (regla `:has(#stemMixerPanel:not(.hidden))` + clase `mixer-open` en `#workspace`).
- **`legacy/DynamicsSpectrumRenderer.js`** (*retirado*): overlay espectral **dry vs comprimido** con ejes puros exportados (`SPECTRUM_RANGE`, `SPECTRUM_GRID_HZ`, `frequencyToX()`, `byteToDb()`, `dbToY()`, `sampleEnvelope()`). El pivote al **scope temporal** (`DynamicsScopeRenderer`) lo dejó sin uso; se movió a `legacy/` y su sección de verificación se retiró (no queda código muerto en `src/web`).
